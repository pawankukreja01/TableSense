# Restaurant and hardware operations
**Operators.** Provision a fresh venue and owner in a non-demo database with `python manage.py provision_venue "Your Restaurant" manager-name --role owner --tables 8`. This prompts for a password. Repeat with a distinct username and --role staff or manager to add an operator. Owner and manager share pilot management permissions. Only staff from the same venue can submit signals or record outcomes. For password resets use Django’s changepassword command. Disable departed accounts. The provision command can add tables to the venue.

**Service setup.** In Menu library add mains, drinks, sides and desserts, set realistic direct variable costs, tags, current prices and review expiry. Use venue-maintained allergen notes and verify ingredient changes with the restaurant. Add rules to connect actual main items or categories to additions. Use the venue’s local time for a service window. Use Service settings to choose brand, session limits, display duration and control allocation. Enter the cashier’s real order first, then use the pilot selector. Select all relevant mains and already-ordered sides and mark any explicit supported dietary preference on each signal. Staff trigger dessert manually.

**Tablet.** Connect to the same HTTPS service from a dedicated browser profile. Generate a code on Table displays, open /#/display?setup=1 on the device and redeem it within five minutes. For a reassignment unpair the old table and pair the new table. Rotate a lost token by unpairing immediately. Clearing site data requires pairing again. Display setup belongs to staff. Keep management credentials off the physical guest tablet. Browser restart at /#/display uses the stored device token. A closed tab or lost network clears cards on next state recovery. If a party leaves unexpectedly, close the session before reusing its table.

**Hardware assessment.** Try a 7–8-inch rechargeable Android tablet in a locked stand and an iPad mini alternative. Use managed Android kiosk mode or iPad Guided Access/MDM as supported, set wake/home URL and test wake after battery drain. Place the display away from spills and diners’ working space. Trial a stable wipe-clean mount, approved charger, cable route, overnight charging, readability, glare and cleaning. Measure battery from seating through close for multiple shifts. Test 12–16 hours as a target. Battery is unavailable on browsers without supported telemetry. Check UK product/electrical safety, EMC/radio, battery transport, disposal and supplier documentation with qualified advisers before purchasing units. Hardware certification and physical shift endurance require separate verification.

**Optional specials.** Set ENABLE_PROMOTIONS=1 and restart. In Approved specials choose a main, a dessert (e.g. Chocolate Brownie), contextual pairing reason, current approved price, actual stock, period, and a use-by cutoff. The manager must confirm suitability, storage and trusted stock. The module only runs on a staff-signalled dessert stage. A stock of zero, withdrawal, expired approval, time cutoff, or unavailable item suppresses it. The display uses the approved price and never claims a discount against an unverified price. Each first staff-fulfilled outcome reduces stock by one. Inventory is manual, so withdraw the special immediately after an outside sale, recall or uncertain availability, then reapprove with the actual count if appropriate. Expiry locally removes a card even if the tablet is waiting for a refresh. No automated food-safety decisions or waste-saved estimates are made.
